# Сервер мировой карты

Общая карта для всех игроков: 10 000 зон, нейтральные армии, захваты, гарнизоны, PvP.
Сервер — единственный источник правды о карте и исходе боёв.

**Стек:** Node.js 24 + TypeScript (запускается напрямую, без сборки) + встроенный SQLite (`node:sqlite`).
Внешних зависимостей нет — `npm install` не нужен.

## Запуск

```bash
cd server
npm start          # http://127.0.0.1:8787
npm test           # тесты правил, боёв, API
npm run dev        # перезапуск при изменении файлов
```

Переменные окружения: `PORT`, `HOST` (для доступа извне — `0.0.0.0`), `DB_PATH`
(по умолчанию `data/world.db`), `MARCH_SECONDS` (длительность похода), `WORLD_SEED`.

Мир генерируется при первом запуске и хранится в базе. Новый мир — удалить `data/world.db*`.

## Запуск на VPS (Ubuntu 24.04)

Хватит самого простого VPS: 1 vCPU, 1 ГБ RAM, 10 ГБ диска. Всё нужное — в `deploy/`.

**Быстро (скриптом):**

``bash
curl -fsSL https://raw.githubusercontent.com/Minlibay/IDLE_Game/main/server/deploy/install.sh -o install.sh
sudo bash install.sh world.example.com   # с доменом: nginx + HTTPS
sudo bash install.sh                     # без домена: http://<IP>:8787 (только для теста)
``

Скрипт ставит Node.js 24, создаёт системного пользователя `idleheroes`, клонирует репозиторий в
`/opt/idle-heroes`, прогоняет тесты, включает службу systemd, настраивает брандмауэр (ufw) и,
если указан домен, — nginx и бесплатный сертификат Let's Encrypt.

**Что где:**
- база мира — `/var/lib/idle-heroes/world.db` (её и надо бэкапить);
- служба — `systemctl status|restart idle-heroes-world`, логи — `journalctl -u idle-heroes-world -f`;
- обновление — `cd /opt/idle-heroes && sudo -u idleheroes git pull && sudo systemctl restart idle-heroes-world`;
- бэкап без остановки — `sqlite3 /var/lib/idle-heroes/world.db ".backup /root/world-$(date +%F).db"`.

**Домен:** A-запись (например `world.вашдомен.ru`) должна указывать на IP VPS до запуска скрипта —
иначе Let's Encrypt не выдаст сертификат. Без домена всё работает по IP, но трафик (в т.ч. токены
входа) идёт без шифрования — годится только для проверки.

**В игре:** на экране входа карты указать адрес сервера (`https://world.вашдомен.ru`).
## Данные

`data/game_data.json` — характеристики отрядов. **Не редактируйте вручную**: единый
источник — `data/units/*.tres` в Godot-проекте. После изменения отрядов:

```bash
Godot.exe --headless --path .. --script res://tools/export_server_data.gd
```

## Правила

- Карта 100×100 шестиугольников (10 000 зон). При смене размера в `config.ts` мир пересоздаётся при запуске: аккаунты и армия с героем сохраняются, замки выдаются заново. Уровень зоны 1 (края) … 10 (центр). Чем ближе к центру —
  тем сильнее нейтралы (`neutralBasePower × neutralPowerGrowth^(уровень-1)`) и больше бонус.
- Новый игрок получает замок в зоне 1-го уровня. Замки захватить нельзя.
- Герой с главной армией ходит только в соседнюю зону, поход длится `marchSeconds`.
- По прибытии: своя зона — переход; нейтралы — бой; чужая зона **без гарнизона и без хозяина** —
  захват без боя; иначе — бой с гарнизоном и хозяином (если его герой стоит в зоне).
- Бой: атака атакующего против защиты обороняющегося (+ уровень героя × `heroPowerPerLevel`),
  удача ±10%. **Проигравший теряет всю армию, герой возвращается в замок.** Победитель
  теряет долю `(сила проигравшего / сила победителя)^1.5`.
- Каждая зона даёт владельцу пассивный бонус (`bonusStats`), он применяется в игре.

Все числа — в `src/config.ts`.

## API

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/api/auth/register` `{name}` | регистрация, возвращает `token` |
| GET | `/api/world?since=N` | карта (0 — целиком, N — только изменения после версии N) |
| GET | `/api/me` | мой герой, армия, поход, бонусы, гарнизоны, отчёты |
| POST | `/api/hero` `{level}` | уровень героя |
| POST | `/api/army/deploy` `{units}` | армия из замка на карту (герой в замке) |
| POST | `/api/army/recall` `{units}` | армия с карты в замок |
| POST | `/api/move` `{zoneId}` | поход в соседнюю зону |
| POST | `/api/garrison` `{units}` | оставить гарнизон в текущей зоне |
| POST | `/api/garrison/withdraw` `{units}` | забрать солдат из гарнизона |

Авторизация: `Authorization: Bearer <token>`.

## Ограничения прототипа (что нужно до релиза)

1. **Экономика на клиенте.** Сервер доверяет числу солдат, которых клиент отправляет на карту
   (`deploy`). Читер может «нарисовать» армию. Нужно перенести найм и ресурсы на сервер.
2. **Вход по имени** — только для разработки. Для Steam: проверка тикета
   (`ISteamUserAuth/AuthenticateUserTicket`) и привязка к SteamID.
3. **Один процесс, SQLite.** Для большого онлайна — PostgreSQL и, при необходимости, шардинг миров.
4. **Опрос вместо push.** Клиент опрашивает сервер раз в 4 с при открытой карте; позже — WebSocket.
5. Крупные ответы (полная карта) сжимаются gzip. Нет защиты от спама запросами (rate limit) и HTTPS — ставится на уровне хостинга (reverse proxy).
