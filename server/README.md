# Сервер игры

Общая карта для всех игроков (10 000 зон, нейтральные армии, захваты, гарнизоны, PvP, набеги на замки)
и экономика замков (ресурсы, казна, стройка, найм и содержание армии).
Сервер — единственный источник правды: клиент только показывает состояние и присылает действия.

**Стек:** Node.js 24 + TypeScript (запускается напрямую, без сборки) + встроенный SQLite (`node:sqlite`).
Внешних зависимостей нет — `npm install` не нужен.

## Запуск

```bash
cd server
npm start          # http://127.0.0.1:8787
npm test           # тесты правил, боёв, API
npm run dev        # перезапуск при изменении файлов
```

Переменные окружения: `PORT`, `HOST` (для доступа извне — `0.0.0.0`), `DB_PATH`
(по умолчанию `data/world.db`), `MARCH_SECONDS` (поход в соседнюю зону), `CASTLE_MARCH_SECONDS`
(поход на чужой замок), `DEV_SPEED` (ускорение стройки/обучения и стартовых ресурсов — только для тестов),
`WORLD_SEED`.

Мир генерируется при первом запуске и хранится в базе. Новый мир — удалить `data/world.db*`.

## Запуск на VPS (Ubuntu 24.04)

Хватит самого простого VPS: 1 vCPU, 1 ГБ RAM, 10 ГБ диска. Всё нужное — в `deploy/`.

**Быстро (скриптом):**

``bash
curl -fsSL https://raw.githubusercontent.com/Minlibay/IDLE_Game/main/server/deploy/install.sh -o install.sh
sudo bash install.sh world.example.com   # с доменом: nginx + HTTPS
sudo bash install.sh                     # без домена: http://<IP>:8787 (только для теста)
``

Скрипт ставит Node.js 24, создаёт системного пользователя `idleheroes`, клонирует репозиторий в
`/opt/idle-heroes`, прогоняет тесты, включает службу systemd, настраивает брандмауэр (ufw) и,
если указан домен, — nginx и бесплатный сертификат Let's Encrypt.

**Что где:**
- база мира — `/var/lib/idle-heroes/world.db` (её и надо бэкапить);
- служба — `systemctl status|restart idle-heroes-world`, логи — `journalctl -u idle-heroes-world -f`;
- обновление — `cd /opt/idle-heroes && sudo -u idleheroes git pull && sudo systemctl restart idle-heroes-world`;
- бэкап без остановки — `sqlite3 /var/lib/idle-heroes/world.db ".backup /root/world-$(date +%F).db"`.

**Домен:** A-запись (например `world.вашдомен.ru`) должна указывать на IP VPS до запуска скрипта —
иначе Let's Encrypt не выдаст сертификат. Без домена всё работает по IP, но трафик (в т.ч. токены
входа) идёт без шифрования — годится только для проверки.

**В игре:** на экране входа карты указать адрес сервера (`https://world.вашдомен.ru`).
## Данные

`data/game_data.json` — отряды, здания и параметры экономики замка. **Не редактируйте вручную**:
единый источник — `data/units/*.tres`, `data/buildings/*.tres` и константы `KingdomState`/`ArmyState`
в Godot-проекте. После изменения отрядов или зданий:

```bash
Godot.exe --headless --path .. --script res://tools/export_server_data.gd
```

## Правила

- Карта 100×100 шестиугольников (10 000 зон). При смене размера в `config.ts` мир пересоздаётся при запуске: аккаунты и армия с героем сохраняются, замки выдаются заново. Уровень зоны 1 (края) … 10 (центр). Чем ближе к центру —
  тем сильнее нейтралы (`neutralBasePower × neutralPowerGrowth^(уровень-1)`) и больше бонус.
- Новый игрок получает замок в зоне 1-го уровня. Замки захватить нельзя.
- Герой с главной армией ходит только в соседнюю зону, поход длится `marchSeconds`.
- По прибытии: своя зона — переход; нейтралы — бой; чужая зона **без гарнизона и без хозяина** —
  захват без боя; иначе — бой с гарнизоном и хозяином (если его герой стоит в зоне).
- Бой: атака атакующего против защиты обороняющегося (+ уровень героя × `heroPowerPerLevel`),
  удача ±10%. **Проигравший теряет всю армию, герой возвращается в замок.** Победитель
  теряет долю `(сила проигравшего / сила победителя)^1.5`.
- Каждая зона даёт владельцу пассивный бонус (`bonusStats`), он применяется в игре
  (бонусы ARMY_POWER и TRAINING_SPEED — и к армии на сервере).

### Замок (`src/world/kingdom.ts`)

- Ресурсы еда/вода/дерево/камень/казна; здания производят их, потолок — склад (казна в 5 раз больше).
- Одна стройка за раз, уровень зданий ограничен Ратушей. Найм — очередь до 5 заказов,
  вместимость армии дают здания; отмена возвращает ресурсы.
- Вся армия игрока (в замке, с героем, в гарнизонах) ест еду. Нет еды — сила армии ×0.5.
- Состояние «догоняется» лениво при каждом обращении (`advanceKingdom`), поэтому замок
  работает и пока игрок оффлайн; фонового пересчёта не нужно.
- Герой ест со склада (`consume`) и вносит золото в казну (`deposit`, лимит
  `depositPerLevelPerMinute × уровень героя` в минуту, копится до `depositBankMinutes`).

### Набеги на замки

- На чужой замок можно пойти, если он не под защитой; поход длится `castleMarchSeconds`,
  защитник видит его в `incoming`. Нужна армия с героем.
- Защищают армия замка + герой с армией, если он дома. Победа атакующего: добыча
  `raidLootShare × (ресурс − raidProtectedResource)`, защитник теряет `raidDefenderLoss` армии
  и получает щит на `raidShieldHours`; герой нападавшего возвращается в зону, откуда вышел.
  Поражение: армия атакующего гибнет, герой — в замок. Если к прибытию замок под щитом — поход срывается.
- Защита новичка `newbieProtectionHours`; снимается, когда игрок сам нападает на игрока.

### Сокровища (именные, уникальные, сетовые)

Каталог — `../data/treasures/*.json` (тот же, что у игры; путь — `TREASURES_DIR`). Сервер хранит, какие
сокровища у игрока (`treasures`), и выдаёт новые по игровому времени: промежутки между запросами игрока
не длиннее `treasureMaxGapSeconds` складываются; раз в `treasureDropMinutes` игры — находка своего класса
(`classId` из `POST /api/hero`), качество по весам `treasureWeights`, не больше `treasureWeeklyCap` в неделю.
В `/api/me`: `treasures`, `treasureNextMs`, `treasureWeekCount`, `treasureWeekCap`. Для тестов —
`TREASURE_DROP_MINUTES=0.05`. На этапе 2 выдачу заменит генератор Steam Inventory (playtime generator).

### Реликвии армии

Герой носит до 6 реликвий; их сумму клиент присылает в `armyGear`. Сервер принимает только
ARMY_POWER, ARMY_ATTACK, ARMY_DEFENSE, TRAINING_SPEED, UPKEEP_REDUCTION и урезает каждый до
`armyGearCaps`. Атака армии в бою = атака отрядов × (1 + (ARMY_POWER + ARMY_ATTACK)/100),
защита — с ARMY_DEFENSE; UPKEEP_REDUCTION снижает расход еды (не больше 80%).

Все числа — в `src/config.ts`.

## API

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/api/auth/register` `{name}` | регистрация, возвращает `token` |
| GET | `/api/world?since=N` | карта (0 — целиком, N — только изменения после версии N) |
| GET | `/api/me` | мой герой, армия, поход, бонусы, гарнизоны, замок (`kingdom`), защита, `incoming`, отчёты |
| POST | `/api/hero` `{level?, armyGear?, classId?}` | уровень и класс героя; бонусы реликвий армии (урезаются до `armyGearCaps`) |
| POST | `/api/army/deploy` `{units}` | солдаты из армии замка на карту (герой в замке) |
| POST | `/api/army/recall` `{units}` | солдаты с карты в армию замка |
| POST | `/api/kingdom/build` `{building}` | начать стройку следующего уровня |
| POST | `/api/kingdom/recruit` `{unit, count}` | заказ на обучение |
| POST | `/api/kingdom/cancel` `{index}` | отменить заказ (ресурсы вернутся) |
| POST | `/api/kingdom/consume` `{resources}` | герой съел еду/воду со склада |
| POST | `/api/kingdom/deposit` `{gold}` | внести золото героя в казну (в пределах лимита) |
| POST | `/api/move` `{zoneId}` | поход в соседнюю зону |
| POST | `/api/garrison` `{units}` | оставить гарнизон в текущей зоне |
| POST | `/api/garrison/withdraw` `{units}` | забрать солдат из гарнизона |

Авторизация: `Authorization: Bearer <token>`.

## Ограничения прототипа (что нужно до релиза)

1. **Герой на клиенте.** Уровень героя, его золото и таланты считает клиент; сервер доверяет
   уровню героя (сила в бою, лимит взносов в казну). Следующий шаг — перенести прогресс героя на сервер.
2. **Вход по имени** — только для разработки. Для Steam: проверка тикета
   (`ISteamUserAuth/AuthenticateUserTicket`) и привязка к SteamID.
3. **Один процесс, SQLite.** Для большого онлайна — PostgreSQL и, при необходимости, шардинг миров.
4. **Опрос вместо push.** Клиент опрашивает сервер раз в 4 с при открытой карте; позже — WebSocket.
5. Крупные ответы (полная карта) сжимаются gzip. Нет защиты от спама запросами (rate limit) и HTTPS — ставится на уровне хостинга (reverse proxy).
